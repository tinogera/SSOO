**Bug 1 — Handler `MSG_CREAR_SEGMENTO` cuando necesita compactación** — ✅ CORREGIDO

Flujo original (roto):
```
KS envía MSG_CREAR_SEGMENTO → KM detecta que necesita compactar
→ KM envía MSG_COMPACTAR a fd_ks               (correcto)
→ KM envía MSG_COMPACTAR a fd (el caller = KS)  ← BUG: responde con mensaje incorrecto
→ No espera MSG_FIN_COMPACTACION antes de responder
```

Flujo corregido:
```
KS envía MSG_CREAR_SEGMENTO → KM detecta que necesita compactar
→ KM envía MSG_COMPACTAR a fd_ks
→ KM bloquea con sem_wait(&sem_compactacion_lista)
→ (MSG_FIN_COMPACTACION llega, KM compacta, señala sem_post)
→ KM reintenta crear_segmento
→ KM responde MSG_TABLA_SEGMENTOS al KS
```

**Bug 2 — Handler `MSG_FIN_COMPACTACION` envía `MSG_FIN_COMPACTACION` de vuelta al KS** — ✅ CORREGIDO

Original: `if (fd_ks >= 0) enviar_mensaje(fd_ks, MSG_FIN_COMPACTACION, NULL, 0)` — causaba un mensaje fantasma al KS.  
Fix: eliminado, reemplazado por `sem_post(&sem_compactacion_lista)`.

**Bug 3 — `list_get_index()` no existe en so-commons** (2 ocurrencias) — ✅ CORREGIDO

En `crear_segmento()` y `dessuspender_proceso()`:  
`list_remove_and_destroy_element(huecos, list_get_index(huecos, h), free)` → `list_remove_element(huecos, h); free(h);`

**Bug 4 — `leer_instruccion()` usada antes de su definición** — ✅ CORREGIDO

Agregada forward declaration `static char* leer_instruccion(uint32_t pid, uint32_t pc);` antes de `atender_cliente()`.

### Prueba de integración mínima

Módulos levantados: KM (puerto 8001) + KS (puerto 8000) + CPU (ID 1).  
Script usado: `scripts/0.txt` (MUTEX_CREATE → MUTEX_LOCK → SLEEP → MUTEX_UNLOCK → EXIT).

```
[KM]  Kernel Memory escuchando en puerto 8001
[KS]  ## Conectado a Kernel Memory
[KS]  ## (0) Se crea el proceso - Estado: NEW
[KS]  ## (0) Pasa del estado NEW al estado READY
[CPU] ## Conectado a Kernel Scheduler / Kernel Memory
[CPU] ## PID: 0 - Proceso recibido de Kernel Scheduler
[CPU] ## PID: 0 - Ejecutando: MUTEX_CREATE - mutex1
[KS]  ## (0) Pasa del estado EXEC al estado READY  ← redespacho tras syscall
[KS]  ## (0) Toma el Mutex mutex1
[KS]  ## (0) - Solicitó syscall: SLEEP → BLOCK
[KS]  ## (0) Pasa del estado BLOCK al estado READY  ← fin de SLEEP (sin IO real)
[KS]  ## (0) Libera el Mutex mutex1
[KS]  ## (0) - Solicitó syscall: EXIT → EXIT
```

**Observación:** sin un módulo IO-SLEEP conectado, el proceso sale de BLOCK casi inmediatamente (el KS no tiene a quién esperar). Para validar el tiempo real de SLEEP hay que levantar IO.
